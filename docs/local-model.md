# Local model installation and benchmarks

Measured results and verification details: [17 October benchmark](benchmark-results.md).

The Windows setup script installs a pinned llama.cpp CUDA runtime and a verified
Qwen3-4B-Instruct-2507 Q4_K_M text model into `%LOCALAPPDATA%/PerfectPupil/local-model`.
Model files, binaries, logs, and the installation manifest stay outside Git.

```powershell
npm run model:setup
npm run model:start
```

Setup uses these upstream artifacts and published SHA-256 digests:

- Runtime: [llama.cpp b11712](https://github.com/ggml-org/llama.cpp/releases/tag/b11712),
  Windows x64 CUDA 12.4, build commit `10b8b7553`.
- Model: [LM Studio's Qwen3-4B Instruct GGUF](https://huggingface.co/lmstudio-community/Qwen3-4B-Instruct-2507-GGUF),
  revision `4edb920b6f14e3b9284d4502a6485103d72cde05`, file
  `Qwen3-4B-Instruct-2507-Q4_K_M.gguf`, 2,497,280,448 bytes,
  SHA-256 `8cdb57cbb880d313736a9bc4e3d3d2485f145b5e19cf33783746e753e82641fc`.
- Original model: [Qwen/Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507),
  Apache 2.0, instruction-tuned without a separate reasoning phase.

The launcher uses one inference slot, 4,096 context tokens, 128-token batches,
six CPU threads, CUDA layer offload, flash attention, and non-thinking mode.
It binds only to `127.0.0.1:8080`; the model's separate Web UI and slot inspector
are disabled. A random API token is stored encrypted with Windows DPAPI and sent
to the runtime through its environment; the app supplies it internally. Inference
requires that token. It leaves an existing server intact and verifies its model ID.

In Perfect Pupil, select **Local model**, base URL
`http://127.0.0.1:8080/v1`, model ID `perfect-pupil-qwen3-4b-instruct-q4_k_m`.
Choose strict JSON schema, temperature 0.3, and 512 output tokens.
Save and test the connection. Once that saved profile is active, `npm start` and
`npm run dev` start the installed model automatically. Ctrl+C stops processes
owned by that launcher; it leaves a pre-existing model service running.

No cloud provider is involved. The model runtime does not depend on Python,
PyTorch, or an installed CUDA toolkit; the verified runtime bundle supplies its
CUDA libraries and uses the installed NVIDIA driver. Model logs are under the
local-model folder. Model configuration does not imply GPU training capability.

## Reproduce an end-to-end benchmark

Start the local model, then run:

```powershell
npm run benchmark:local -- --output output/local-benchmark --repeats 2 --extra-probes
npm run test:browser -- --real-model
```

Each benchmark creates its own application service and SQLite database. It uses
real HTTP inference and does not read the user's companions or conversations.
It records full test responses, scenario assertions, total request latency,
provider token/timing metadata, context sizes, and NVIDIA memory samples.
Fallback is disabled so a scripted reply cannot count as a successful model run.
Inspect `report.json`, especially failed cases and recorded model responses.
Failed scenario checks produce a nonzero exit status. The extra probes have
informed prompt improvements and are regression tests, not a sealed holdout.
Memory-proposal confirmation text is generated by the app; reports retain the
original model output and mark the reply's source explicitly.

Reported latency is time until a complete response; the app does not stream
tokens. Runtime generation tokens/second excludes prompt processing. Neither is
a measurement of first-token latency. Scenario checks provide regression
coverage, not a general intelligence or safety certification. Qualitative
review and unseen probes remain necessary after changing a prompt or model.

The benchmark is intended for the inspected RTX 2050 4 GiB / roughly 16 GiB RAM
PC. Other workloads, power limits, temperature, driver version and available
system memory affect speed; compare runs under similar conditions.
